# `bots` — State machines

*Which states exist, which events move between them, and which moves are refused?*

Two machines, each declared as data in one file with its states and events (`code/quality.md` §3).
Any pair a table does not list is refused: `next_target` raises `InvalidBotTransitionError`,
`next_level_state` raises `InvalidLevelTransitionError`. The tables below are **generated** from the
code by `python3 scripts/render_bots_design_tables.py --write`, in the order the code declares them;
`tests/unit/scripts/test_render_bots_design_tables.py` fails when one differs from a fresh render. Do
not edit them by hand. Design: ADR 029 §3.1 and §3.2 ([`09-decisions.md`](09-decisions.md)).

## Built: the bot lifecycle

`bots/domain/bot_lifecycle_fsm_matrix.py` → `BotLifecycleState`, `BotLifecycleEvent`,
`BOT_LIFECYCLE_TRANSITIONS`: nine states and fifteen events. Two targets are not states, and the table
says so: `REMOVED` (`delete` from `DRAFT` or `STOPPED`; the store deletes the file) and `PRIOR`
(`reconcile_ok` from `RECOVERING` returns to the state the bot was in before the restart, which `Bot`
remembers as `recovering_from`; `BotLifecycleTarget`). `app_restart` is the restore rule written as a
transition ([`06-runtime.md`](06-runtime.md)). `resume` from `RECOVERING` is a self-loop (`BUG-204`):
the reconcile decides the next state, not the click.

## Built: a Grid level

`bots/domain/grid/grid_level_fsm_matrix.py` → `LevelState`, `LevelEvent`, `GRID_LEVEL_TRANSITIONS`:
five states and seven events. The live executor and the backtest share this table, so a fill means the
same thing in both. `ended` (cancelled, expired or refused without filling whole) returns a level to
`EMPTY` and the runtime counts the end; `adopt` is the reconcile finding an order carrying the bot's
tag at a level the saved state did not know; `settled` is a filled level returning to `EMPTY` once its
counter order is laid. `HOLDS_ORDER` is the set of states with an order on the exchange.

## Planned: EPIC-039L, the protective stop's life cycle

A third machine, one per protective order, declared as data in `bots/domain/grid/` when C2 builds it
(`code/quality.md` §3); this table is the design, written by hand until the code exists and then
replaced by a generated one like the two above. Any pair it does not list is refused.

| From | Event | To |
| :--- | :--- | :--- |
| `ABSENT` | `intend` (the account position on the symbol is non-zero and the plan has a stop-loss price) | `INTENDED` |
| `INTENDED` | `accepted` | `STANDING` |
| `INTENDED` | `rejected` | `ABSENT`; the position is closed if one stands, nothing is closed if none does |
| `INTENDED` | `lost_answer` | read by `clientAlgoId`: found, `STANDING`; not found, send again |
| `STANDING` | `triggered` (from the algo status, read by `clientAlgoId`) | `TRIGGERED` |
| `STANDING` | `exposure_closed` (the bot's position is zero and the exchange's is zero, dust or foreign) | `CANCELLING` |
| `STANDING` | `expired` or `missing_with_position` | `ABSENT`; `intend` again when a position stands |
| `CANCELLING` | `cancelled` or `unknown_order` | `ENDED` |
| `TRIGGERED` | `settled` (flat confirmed, the sibling order cancelled) | `ENDED` |

`ENDED` is terminal and the record is dropped on the next save. A `STANDING` stop outlives its run under
custody (a kept position); the bot is `STOPPED` or `HALTED`, the record is not. The refused moves that
matter: no `STANDING` to `CANCELLING` while the bot's exposure is not read closed; no cancel of a stop by the ladder's
cancels. The reconcile table (position against stop) is in
[`06-runtime.md`](06-runtime.md) and in the decision record §3.2.
