# BOT-195 — The human text report prints as a `rich` table on a terminal and stays byte-identical everywhere else

**Status:** 🔵 Backlog
**Priority:** P2
**Board:** `bot list`, `bot show` and the other text reports print as a `rich` table with meaning colour on an interactive terminal; JSON, piped text, `NO_COLOR`, `TERM=dumb` and a missing `rich` keep today's bytes ([PRO-017](proposal/PRO-017.md)).
**Source:** The owner, 2026-10-19: *"làm task theme UI, với 1 task là tui muốn dùng rich cho VPS, đánh giá và làm nhé"* ("do a UI theme task, and one task where I want to use `rich` on the VPS: evaluate it and build it"). The delegation to add the dependency is recorded in PRO-017.
**Risk:** 🟡 — a new dependency on the VPS and a second text path; the risk is a byte change to piped text, which the tests pin.
**Complexity:** M — one renderer, one chooser, three pins, tests and a runbook paragraph.

## 1. Context and problem
`TextReportRenderer` prints a `Report`'s layout as padded plain text; the owner reads it in an SSH terminal and wants tables and colour there. PRO-017 evaluated `rich` (licence MIT, pure Python, 3.12 floor met, no effect on JSON or Discord) and recommends a terminal-only renderer behind the existing `IReportRenderer` seam.

## 2. Acceptance criteria
- [ ] With the text format and stdout an interactive terminal, `TERM` not `dumb`, `NO_COLOR` unset and the terminal at least as wide as the table, a report prints through `rich`; a state word and a profit or loss sign are coloured and still printed as words and signs.
- [ ] In every other case (stdout not a terminal, `NO_COLOR` set, `TERM=dumb`, terminal too narrow, `rich` not importable) the output is the `TextReportRenderer` bytes, equal to the existing golden strings.
- [ ] `--json` output is byte-identical with a terminal and without one, and `rich` is never imported on that path.
- [ ] Output that is not a terminal holds no ANSI escape sequence and no box-drawing character.
- [ ] `rich` is named in `requirements.txt` and `requirements-headless.txt` and pinned, with its dependencies, in `requirements.lock` regenerated by `uv pip compile`.
- [ ] `Docs/OPERATIONS/headless_runbook.md` says what changes on a terminal, that piped and `--json` output do not, and how to switch it off (`NO_COLOR=1`).

## 3. Design
A third renderer, `RichTextReportRenderer`, registered beside `text` and `json`; `emit_report` asks one chooser (`choose_text_renderer`) which of the two text renderers to run for the `text` format. The chooser reads `isatty()`, `TERM`, `NO_COLOR` and the terminal width through a small environment port so tests set them without a pty. `rich` is imported inside the renderer's method, not at module top, so a piped run and a venv without `rich` pay nothing and cannot fail. A section whose rows all have the same number of cells and whose first row is a header prints as a `Table`; a row of label and value prints as a two-column block. Colour comes from one named meaning table in the renderer (state word to style, `+` and `-` to style); the `Report` stays neutral (PRO-017 §4). Reporting style, not data: nothing in a payload changes.

Source: `CONSTITUTION.md` P5 (a vetted library), P7 (the renderer seam exists), Open-Closed in `i_report_renderer.py`.

## 3a. Reuse
`IReportRenderer`, `ReportFormats.register`, `emit_report` and `TextReportRenderer` (the fallback and the byte reference) are used as they are. No UI catalogue row applies (`None: no Qt UI need`).

## 5. Testing
Unit tier. (a) Golden: for `bot list`, `bot show` and `exchange-status` reports the plain renderer's bytes equal the existing strings when stdout is not a terminal, `NO_COLOR` is set, `TERM=dumb`, the width is too small, or `rich` is made unimportable. (b) `--json` is byte-identical with the terminal faked on and off, and `rich` is not in `sys.modules` afterwards. (c) With the terminal faked on, the output holds ANSI and the state and sign words. (d) Non-terminal output matches `^[^\x1b]*$` and holds no box-drawing character. (e) `test_dependency_pins.py` stays green. Not run: a real Windows console (PRO-017 unknowns).
