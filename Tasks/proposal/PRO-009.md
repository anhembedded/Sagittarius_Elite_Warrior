# PRO-009 — The desktop app looks and reads like a financial application, without bringing back a theme layer

**Date:** 2026-10-13
**Status:** Proposed
**Source:** The owner, on the plain native look: *"add màu, theme cho app này thì có mất nhiều công sức ko bạn, UI bây giờ đơn điệu lắm thiếu nhiều design đặc trưng của 1 app tài chính"* (would adding colour and a theme take much effort? The UI is very plain and lacks the design of a financial app). After the coordinator's options they asked for this proposal: *"Oki tạo Pro-009"*.
**Decision:** Pending (the owner).

## 1. Problem and evidence
**The plainness is deliberate, not an accident.**
- `EPIC-033` D1, the owner's decision, made every control a stock Qt class in the platform style: *"làm 1 UI sơ đẳng, nhưng đúng triết lý Window app trước, chưa cần tính đến design"* (a plain UI true to the Windows philosophy first; design later).
- D8, an agent decision, says dark mode is the operating system's colour scheme, never an app theme.
- HLD §11.4 records the designed theme as *"explicitly deferred by the user"*.
- `EPIC-033M` deleted the old theme layer (`kit/style.py`, `qdarktheme`, per-widget style sheets). Guards keep it deleted: `test_no_global_stylesheet.py`, `test_stock_controls_only.py` and `test_app_styling_only_shrinks.py`.

That layer was removed for a measured reason. The `EPIC-033` UI review found three visual systems at once, up to 90 styled widgets per screen, and fixed sizes that broke at 1024×700. This proposal is the deferred "design later" step, and it must not reintroduce those causes.

**What exists today (checked 2026-10-13 at `c5fe7c7`):**
- `src/support/ui_kit/meaning_colours.py` is the one meaning table. `Tone.POSITIVE` / `Tone.NEGATIVE` map to the chart's bull and bear colours.
- It is used only in `backtesting/ui` (4 files). The Bots, trading and market screens show profit, loss and state in the platform's text colour.
- `src/support/charting/contracts/series_colours.py` holds the data series colours. Chart chrome follows `QPalette` (`chart_card/chart_chrome.py`).
- The app pins no `QStyle` and sets no colour scheme. With PySide6 6.11 on Windows, the default style follows the system's light or dark setting.

**Unknown:**
- Whether every screen and the pyqtgraph canvas read well when Windows is switched to dark mode. Nobody has looked.
- Which financial cues the owner values most. The list in §2 is the coordinator's reading of "đặc trưng app tài chính".

## 2. Intended outcome and scope
The app reads as a trading application at a glance, while staying a stock-widget desktop app that the existing guards still protect.

**A. Light, dark and system colour schemes, chosen in the app.**
- Tools → Options gets a choice: System (the default), Light or Dark.
- It is applied with Qt's own `QStyleHints.setColorScheme` (Qt 6.8+), so the platform draws its own dark palette. The app writes no palette, no style sheet and no colour.
- Chart chrome already follows `QPalette`. Series colours are checked for contrast in both schemes, and one alternative value per scheme is added where a colour fails.

**B. A financial visual language, built only from what the rules already allow.**
1. **Profit and loss everywhere.** Every PnL, return and change figure on the Bots, trading and market screens is coloured by `Tone`, with the sign and an arrow (▲ ▼) kept in the text. This reuses `meaning_colours.py`; no new colour.
2. **State badges.** A bot's or connection's state is a word plus an icon, coloured by a small extension of the meaning table: running, paused, halted, recovering, disconnected.
3. **Headline figures.** The key numbers (equity, today's PnL, open position, liquidation distance) sit in one row above the detail. They use a larger size and bolder weight derived from the system font, as the rule allows, and the platform's fixed-pitch font for digits.
4. **Live price movement.** A price cell briefly takes the up or down tone when it ticks, then returns to the platform colour. The arrow stays as the non-colour signal.
5. **Risk colour.** The liquidation read-out and the risk watch's SAFE / WARN / CRITICAL use a warning tone that already has a word beside it.
6. **Icons.** Commands and states get SVG icons from the existing Lucide set.

**Success criteria:**
- Every screen is readable in light, dark and Windows High Contrast.
- The conformance suite passes at all three sizes in both schemes.
- `test_stock_controls_only.py` and `test_no_global_stylesheet.py` stay unchanged, or are tightened.
- Each new colour lives in the meaning table, with a word or sign beside it.
- A before/after `preview.py` frame for each touched screen.

**Out of scope:**
- A brand, custom-drawn widgets, any style sheet, a third-party theme package, card layouts and fixed sizes. These are option C below.
- Animations beyond the tick flash.

## 3. Options and trade-offs
| Option | Benefit | Cost and risk | Evidence or precedent |
| :--- | :--- | :--- | :--- |
| Keep the current approach (wait for Windows dark mode) | Nothing to build | Still plain. No in-app dark choice. Profit and loss stay uncoloured outside backtesting | D1, D8, HLD §11.4 |
| **A + B: colour scheme through Qt, plus a meaning-driven financial language** | Dark trading-terminal look and financial cues. One mechanism per concern (`setColorScheme`, the meaning table). The guards stay as they are | About 4 tasks: A ≈ 1 small task; B ≈ 3 tasks (PnL and badges; headline figures and the tick flash; risk tones and icons). D8 changes wording: "the OS scheme, or the one the user picks in Options", still never an app palette | Qt 6.8 `QStyleHints.setColorScheme`; `meaning_colours.py` and `Tone`, already used in backtesting; MS `vis-color` and KDE "colour never alone", already cited in the rule |
| C: a designed theme (style sheet, custom palette, brand, custom widgets) | Maximum freedom of look | Large. Reverses D1, D8 and `EPIC-033M`, which removed exactly this after it caused three visual systems and broken layouts. Every new widget must be styled by hand forever | `EPIC-033` UI review; `kit/style.py` history |

## 4. Recommendation
Adopt **A + B**, in this order:
1. **Verify first.** Switch Windows to dark mode and screenshot every mode at 1366×768. This costs an hour, tells us what already works, and may reduce A to the Options switch alone.
2. **A:** the Options choice of colour scheme, plus a contrast check of the series colours in both schemes.
3. **B1 and B2:** profit and loss everywhere, and state badges. These give the biggest visible gain for the least code.
4. **B3 and B4:** headline figures and the tick flash.
5. **B5 and B6:** risk tones and icons.

**Open questions:**
- Whether the owner wants Dark as the default instead of System. That is a one-line change in A.
- Whether the tick flash is wanted at all; some traders find it distracting. It could be an Options toggle, off by default.
- Proposed record: D8 is amended, not reversed. The colour scheme becomes a user choice, applied through Qt; the app still never writes a palette.

## 5. Decision needed
The owner decides whether to accept A + B. Accepting does three things:
- amends `EPIC-033` D8 and HLD §11.4 (the colour scheme may be chosen in Options);
- keeps D1, with no style sheet and no custom look;
- adds a small UI epic, scheduled after `EPIC-039`'s testnet run unless the owner says otherwise.

Choosing option C instead reverses D1 and `EPIC-033M`, and needs its own decision record.
