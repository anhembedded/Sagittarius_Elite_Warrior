# PRO-007 — A running bot's performance and risk figures

**Date:** 2026-10-09
**Status:** Proposed
**Source:** The owner, while running bot `ke95g7` on Spot Mainnet: "bot nói chung phải show được realtime đang lời lỗ bao nhiêu… bạn còn gợi ý chỉ số nào khác ko" (a bot must show how much it is gaining or losing in real time; which other figures would help). The owner also asked for a proposal only, with no implementation, and called these figures secondary.
**Decision:** Pending

## 1. Problem and evidence
The bot's Plan panel already shows Total PnL, *of which grid profit*, *of which unrealised* (with the price it was valued at), the HODL benchmark, Held and Running time. The owner checked this on a screenshot of `ke95g7` on 2026-10-09. Three gaps remain:
- The figures appear only for the selected bot. The bot list has no PnL column, so the owner cannot compare several bots at a glance.
- PnL is an absolute amount. It is not shown as a percentage of capital, nor annualised.
- Nothing shows how far the price is from the bot's exits (stop loss, the ladder's bounds), or how much of the capital has become base asset.

Unknown: whether the existing figures refresh on every tick. The screenshot shows a valuation price next to the unrealised figure, but this proposal did not measure the refresh cadence.

## 2. Intended outcome and scope
The owner can tell from the bot list which bots are making or losing money, and which are close to an exit, without opening each one. The Plan panel also gives the risk figures for the selected bot.

Constraints:
- Every figure is derived from facts the app already has: fills, the price tick, the plan and the run start. No new exchange read is added.
- Each figure states when it was computed.

Out of scope: alerts on these figures (EPIC-036 owns alerting), charts beyond the existing Equity panel, and futures-specific figures.

## 3. Options and trade-offs
| Option | Benefit | Cost and risk | Evidence or precedent |
| :--- | :--- | :--- | :--- |
| Keep the current approach | No work | The owner opens each bot to see whether it makes money; nothing warns before the stop loss | Today's Plan panel |
| A. List columns: status, Total PnL, PnL %, APR, distance to SL. Panel: break-even price | Smallest change with the largest effect; one glance answers "is it working, is it in danger" | One read model for the list, plus formulas that need tests (APR over short runs is noisy) | Grid bots on major exchanges show PnL %, APR and the price range in their bot lists |
| B. Option A plus a full figure set in the panel, grouped as **Result** and **Risk** | Complete picture | More UI and more formulas to verify | Same precedent |

The full figure set for option B:
- **Result:** Total PnL and PnL %; annualised APR of grid profit; matched round trips, total and in the last 24 h; fees paid; the difference against HODL in %.
- **Risk:** break-even price of the base held; distance in % to the stop loss and to each ladder bound; share of capital held as base versus quote; the run's maximum drawdown.
- **Efficiency:** the share of the run's time the price spent inside the ladder.
- **Chart:** an equity or PnL line in the existing Equity panel, which is empty today.

## 4. Recommendation
Option A first. Its figures answer the owner's question directly and are the cheapest to verify. Option B's remaining figures can follow as one task each.

Unresolved questions:
- Should APR be hidden until a run has lasted a minimum time, for example 24 h, so a short run does not show a misleading figure?
- Should the distance to SL turn amber below a threshold? That overlaps with EPIC-036's alerting, so it is better decided there.

## 5. Decision needed
The owner decides under ONBOARDING §7 whether to accept option A, option B, or neither. Accepting commits the project to one task (a list read model, the formulas with tests, list columns and panel rows). It does not schedule the work.
