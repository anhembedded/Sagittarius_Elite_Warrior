# BUG-007 — Closing the desktop app leaves the Python process running

**Reported:** 2026-08-17  
**Status:** Fixed by `BOT-099`  
**Evidence:** User runtime log ending with `App stopped.` while the terminal/process remains blocked

## Reproduction

1. Open the real desktop app.
2. Start Backtest data sync for a long range (observed: BTCUSDT 1m, one year).
3. Close the app while `PythonBinanceClient.get_historical_klines()` is still
   consuming the Binance generator.
4. Engine logs scheduler/service/extension/async-runtime shutdown and
   `App stopped.`, but the Python process does not exit.

## Root cause

`ThreadManagerExtension.shutdown()` calls `ThreadPoolExecutor.shutdown(wait=False)`.
That returns immediately but cannot stop a running function; Python still joins
executor worker threads during interpreter shutdown. Backtest sync has no
cancellation token and the Binance pagination loop has no cancellation check,
so the network worker outlives the UI and engine lifecycle log.

## Why sanity missed it

Sanity is construction-only by project rule. Existing tests boot and stop an
idle engine in the same pytest process; they neither start a long network task
nor assert that a child process exits within a deadline. `app.stop()` returning
is not equivalent to all non-daemon workers terminating.

## Acceptance criteria

- Backtest sync owns a cooperative cancellation token.
- Closing the MainWindow cancels active presenter work before engine shutdown.
- Binance historical pagination observes cancellation between yielded rows/
  request pages and never persists a partial cancelled result.
- Late callbacks cannot mutate a closed UI.
- An isolated process-level regression starts an in-flight deterministic sync,
  closes the app and proves the child process exits within a bounded deadline.
- Idle boot/stop sanity remains construction-only and is not relabeled E2E.
- Full CI passes in both engine and bot repositories.
