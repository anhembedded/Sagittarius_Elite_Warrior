# BUG-242 — Switching between two bots leaves the first bot's editor panel on screen, over the docks, and the workbench chart says candles are missing for no symbol

- **Reported:** 2026-10-20 (the owner, on Windows after pulling `EPIC-040E`, through the coordinator session: *"switch 2 bot, bị lỗi. cái control panel của bot vừa switch nó không được xóa. lỗi xuất hiện lâu rồi, mà giờ mới thấy ảnh hưởng"*)
- **Severity:** 🟡 P2 — a stray window of the previous bot's parameters covers the Bots and Strategies docks; a person may read or edit the wrong bot's numbers. No order is sent by it.
- **Status:** ✅ Fixed (2026-10-20)
- **Board:** Cause: a slot took a widget out with `setParent(None)` while its layout's queued show was still pending, so the widget appeared as a parentless window (the previous bot's `GridPanel`, a retired workbench page); the workbench chart read a drawing with no symbol as an empty load. Fix: `replace_in` hides, then keeps a child of the slot's owner or deletes a disposable widget; `BotChart` shows its notice only for a shown symbol.
- **Context:** Run a Grid bot (`Docs/SPEC/SPEC-014_run_a_grid_bot.md`, selecting a bot) → Module `src/modules/bots/` → `ui/bots_screen/` (slots), `ui/chart/` (the chart notice)
- **Environment:** The owner's Windows desktop after `EPIC-040E` (`cd121a5`). Reproduced offscreen here at `cd121a5`; the Windows screenshot itself was not available to this session.

## Reproduction
1. Two bots in the Bots mode, the window shown. Select the first, then the second, then the first again within one pass of the event loop (a fast click-through, or a keyboard repeat).
2. Expected: only the selected bot's editor in the Plan dock, nothing else on screen.
3. Actual (offscreen, before the fix): the editor built for the bot no longer selected is left alive as a hidden top-level `GridPanel` (`QApplication.topLevelWidgets()` holds it), and so is every retired workbench page; swapping a widget out within one pass of the event loop shows it as a visible window (`test_a_kept_widget_shows_again_when_it_comes_back`). On a desktop a visible parentless window opens at the screen's corner, over whatever docks are there. With the Backtest tab in front, the workbench chart also says "No candles are stored for  at 15m" (an empty symbol) before anything ran.
4. Not reproduced: the owner's visible stray panel through the real Bots screen offscreen, and the screenshot's sandbox banner needs a retired workbench page, which only a venue change retires (two bots on one venue retire only the kind editor); the owner is asked which venues the two bots were on. Sequential selections leave the retired widgets hidden, not visible; what makes one visible on Windows is not established here beyond the queued show above, which is the only mechanism found that shows a parentless widget.

## Symptom
The owner's report (above). The screenshot showed the previous bot's sandbox banner and editor drawn over the Bots dock and the Strategies dock, and the workbench chart's text with the empty symbol. Reproduced here: the text "No candles are stored for  at" on the workbench chart, and parentless top-level widgets left behind (above).

## Root cause
Two mechanisms, both at `cd121a5`:
1. `src/modules/bots/ui/bots_screen/widget_slot.py:16`, `replace_in` took each retired widget out with `setParent(None)`. A parentless widget is a window of its own; Qt hides it on reparenting, but a layout shows each widget it takes in by a call queued on the event loop (`QLayout.addChildWidget`, `_q_showIfNotHidden`). When a widget is swapped out again before that call runs (two selections in one turn), the queued show runs on the parentless widget and opens it as a window. The Plan dock builds a new kind editor for every selection (`selected_bot.py:229`), so each swap was one such widget; the retired Backtest workbench pages (`backtest_workbenches.py`, one per venue) and the workbench's sandbox editor (`backtest_workbench_view.py:214`) went the same way. The bug is old (the Plan dock) and `EPIC-040E` made it visible by putting the workbench's pages through the same slot.
2. `src/modules/bots/ui/chart/bot_chart.py:77-82`, `BotChart._on_history_drawn` treats every empty drawing as "the shown symbol has no stored candles". The workbench's result chart is a `BotChart` that never shows a symbol and is cleared with an empty drawing whenever a bot is followed (`BacktestWorkbenchView.clear_result`), so it said so with `shown_symbol == ""`. It shares the "no candles" cause only in being a `BotChart`; its fix is its own.

## Fix
- `widget_slot.replace_in`: a widget leaving is hidden first (a queued show respects that), then, if it declared itself disposable (`WA_DeleteOnClose`) it is closed and so deleted, and otherwise it stays hidden as a child of the slot's owner, never a window; the widget coming in is shown explicitly (a hidden widget is not shown again by a layout).
- Disposable by declaration: the notes a slot shows when it has nothing (`BotsView._note`), the kind editor built for a selection (`BotPlanPanel.set_kind_panel`) and the workbench's sandbox editor (`set_editor` deletes the one it replaces). Kept: the bot's chart card and a workbench page per venue, which their owners bring back.
- `BotChart._on_history_drawn`: the missing-candles notice only when a symbol is shown.
- The scan the coordinator asked for: every `setParent(None)` in the bots slots was this pattern and is gone. Four remain elsewhere in `src/`, checked and left: `backtest_modals/indicator_picker_dialog.py:76` and `limitations_dialog.py:95` and `ui_kit/readout_slot.py:85` are each followed by `deleteLater()`, and `ui_kit/param_form/strategy_params_dialog.py:218` (`_rebuild_fields`) retires a widget nothing else references, which Python deletes. The defect needs a retired widget that something keeps alive: a workbench page held by `BacktestWorkbenches`, and a `GridPanel`, which its own lambdas (`grid_panel.py`, connected to its own actions) keep alive through a cycle the collector never frees, so before the fix every selection left one hidden top-level `GridPanel` alive (found by the reviewer with `gc.get_referrers`). The commit body's "none remains" is wrong for these four; this report is the correction.
- Review round 1: `replace_in` leaves a widget it is handed back alone (it had deleted a disposable one put back in its own slot), and refuses a slot that is not installed in a widget (it would have retired into a window of its own).

## Regression test
`tests/unit/modules/bots/ui/bots_screen/test_switching_bots_leaves_nothing_behind.py` (three tests, through the real Bots screen and the workbench host) and `test_a_swapped_out_widget_is_never_a_window.py` (three, on the helper). Each was run alone against the code before the fix and failed for the reason above (the first bot's editor still alive; the notice text present; the retired page a window; a kept widget a window and a queued show making it visible; a disposable widget not deleted) and passes after. A seventh test, "two quick selections leave no window", passed before the fix when run alone (it had failed only through a sibling's leaked widget), so it was deleted as vacuous.
