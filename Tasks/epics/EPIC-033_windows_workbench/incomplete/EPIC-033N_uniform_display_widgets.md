# EPIC-033N — Every table, list and read-out is built from one spec per kind

**Status:** 🟡 In progress — tables, the formatter (P4d) and per-symbol precision on the desk and the Watchlist done; read-outs, grouped trees and the backtest trade log open
**Source:** the user, 2026-10-04 — "ko chỉ cần control thống nhất, mà các widget hiện thị cũng phải thống nhất, ví dụ mấy cái mảng thì phải thông nhất các properti" (not only the controls: the display widgets must be uniform too, e.g. the tables must share the same properties).
**Risk:** 🟡 — every data view changes how it sorts, aligns and formats
**Complexity:** M — 12 item views, every read-out form and every display formatter
**Epic:** [EPIC-033](../README.md)
**Depends on:** Engine W6, EPIC-033C

## 1. Context and problem
The 12 item views in `src` are configured by hand, one file each: selection behaviour is set on 8, edit triggers on 4, header resize modes by 26 separate `setSectionResizeMode` calls, numbers right-aligned in 8 places. The Watchlist gives Symbol ~880 px and squeezes the numbers. Values are formatted by per-screen helpers (`kline_inspector_table_model._format_price`, `trade_log_row._format_datetime`, `trade_log_row._format_compact_usd`, `amount_text.format_amount`, …), so one price prints differently on two screens. Read-outs (Available / Max buy / Total / Est. fee) are label pairs laid out per panel.

## 2. Acceptance criteria
- [x] Every `QTableView`/`QTreeView`/`QListView` in `src` is built through the Engine's `configure_item_view()` with a `ColumnSpec` per column; no view sets selection, edit triggers, sorting, header resize or alternating rows itself (033B static ban). — Every flat table is (11 views: positions, open orders, holdings, order and trade history, watchlist, database status, K-line inspector, bots, bot orders, bot fills, plus the symbol picker); `item_view_config` in `baseline_stock_controls.json` fell from 69 to 13. The four grouped `QTreeWidget`s are done ([`BOT-151`](../../../completed/BOT-151_grouped_trees_from_specs.md), 2026-10-06): the three Backtest read-outs became flat tables from column specs in `EPIC-033L`, and the timeframe picker is configured in place by the Engine's `configure_item_view(tree, None, specs)`; `item_view_config` is 0.
- [x] A column's kind alone decides its alignment (text left; quantity, price, percent, money right; timestamp and side fixed), width policy (content-sized; one stretch column), sort role (the raw value, never the display string) and display text. — The Engine's proxy and delegate; `test_spec_table.py` (a timestamp column sorts: `RowTableModel` serves a `datetime` as POSIX seconds, since Qt cannot order a Python object — the review of PR #351 found every timestamp column unsorted), `test_positions_panel.py` (`test_pnl_sorts_by_the_number_not_by_its_text`), `test_database_status_table_model.py` (timeframes sort by length). The stretch column is the one whose content varies most (symbol, name, client order id, status), not always the last text column.
- [ ] Every displayed number, price, percent, money amount, duration and timestamp goes through the app's `ValueFormatter` implementation (precision per symbol from exchange filters, one timestamp format, one percent format); the per-screen helpers are deleted. — `AppValueFormatter` (`src/support/ui_kit/value_formatter.py`, `test_value_formatter.py`) writes every table cell, the order book's confirmation questions, the bot facts and the stored-records tile; `_format_price`, `_format_volume`, the row builders' f-strings, `as_number` and the bots' `amount_text`/`signed_text` are deleted. Precision per symbol is done for the desk's tables (positions, open orders, order and trade history) and the Watchlist: a cell answers the Engine's `PRECISION_ROLE` with its symbol's tick or step size and `AppValueFormatter` writes the value in whole quanta, falling back to the magnitude rule while a symbol's filters are unknown (`ISymbolPrecisions`, `RowTableModel.SYMBOL_QUOTED`). **Open:** the bots' tables (their rows name a bot, whose symbol's filters the Bots mode does not hand its tables yet); the backtest trade log (`trade_log_row`, widget rows, 033L) and the order panel's `amount_text` (an editable field's round trip, not a display) still format their own. **Also owed here** (moved from `EPIC-033B`, 2026-10-06): the static ban in `test_stock_controls_only.py` on a number or time formatted for display outside the formatter, which lands once the per-screen helpers are gone.
- [ ] Every label–value read-out is a `ReadoutForm`; values align to the same column and use the formatter. — Done (P4e) for the account summary, the order form's figures, the bot facts, the trading session probe and Dev Board's Trading Session card: the Engine's `ReadoutForm`, or `ReadoutSlot` (`src/support/ui_kit/readout_slot.py`) where the rows follow the account or the symbol; units in the titles, values by `AppValueFormatter`. **Open:** the backtest report's figures and Monte Carlo summary (owned by `EPIC-033L`, which rebuilds the Backtest mode), Data's stat tiles (`EPIC-033J`), and the grid bot's backtest summary (`grid_backtest_view.py`, a `QFormLayout` of figures with their caveats; owned by `EPIC-033K`, which rebuilds the Bots mode).
- [x] Empty data shows one empty state per view kind (placeholder text in the view, not a separate panel). — `SpecTable` wraps the view in the Engine's `EmptyStateStack`; the history panel keeps its own page because it says three things (reading, an error, no rows).
- [ ] The conformance suite checks each visible column's alignment against its kind's (numbers, money and durations right; text, identifiers and dates left), so a view whose delegate or model overrides it fails. — moved from `EPIC-033B`'s first criterion (2026-10-06): `item_view_conventions` checks that a view was configured from its specs, not what each column shows.
- [ ] Columns whose digits align (price, quantity, money) use `QFontDatabase.systemFont(FixedFont)`, decided by the column kind, never per view (D6). — moved from `EPIC-033C` (2026-10-06), whose half, the application font, is done.
- [x] 033B's conformance check finds no visible view whose properties differ from its spec. — `item_view_problems` now fails a visible table or tree not configured from its specs (red when `tblWatchlist` loses the mark).

## 3. Design
Declarative column specs as in Qt's own model/view practice and every trading terminal's grids (P5): the model exposes raw values in `Qt.UserRole` and display text through the formatter; the view never decides presentation per screen. Mechanism (spec, kinds, view configuration, read-out form, formatter port) is Engine W6; policy (which kinds a table has, precision per symbol) is the app's (TASK-043's split: the Engine owns mechanism, the app owns policy).

## Implementation notes (written when done)
P4d (the PR with `EPIC-033G`) carries the tables and the formatter; the open criteria above stay with this task.

- **Mechanism.** `RowTableModel` declares `COLUMNS: tuple[ColumnSpec, ...]` and one `_value()` that returns the raw value; `HEADERS`, `RIGHT_ALIGNED`, `_display_text`, `_sort_value`, `SORT_ROLE` and `as_number` are deleted. `RowTableModel.column(key)` replaces the per-model index constants. `SpecTable` (`src/support/ui_kit/spec_table.py`) builds the view through `configure_item_view` with `APP_VALUE_FORMATTER` inside an `EmptyStateStack`, and maps selections through the proxy; `displayed_text()` reads a cell through the view's own delegate, which is what the panel tests assert.
- **Rows hold values.** `PositionRow`, `OpenOrderRow`, `HoldingRow`, the two history rows and `KLineDisplayRow` carry `Decimal`s, floats and `datetime`s instead of pre-formatted text; `display_number()` handed Qt a float to sort on until the Engine's proxy learned to order a `Decimal` (2026-10-06), and the models now serve the `Decimal` itself. `DatabaseStatusDTO` carried display strings from the application layer (`"N/A"`, `str(count)`) and the presenter parsed one back (`int(str(...).replace(",", ""))`); it now carries `datetime | None` and `int`.
- **Timeframes.** A timeframe column is `DURATION` with `TIMEFRAME_KEY`: its cell holds seconds, so `1m` sorts before `15m` before `1h`, and the formatter writes the code back.
- **Read-outs (P4e).** `ReadoutSlot` holds the `ReadoutForm` for the rows a `Readout` declares and rebuilds it only when they change (an account learns USDT or USD from its first read; an order form's units follow the symbol), otherwise it only writes values. It takes the old form out of itself at once, not only when the event loop deletes it, and `value_label()` looks only in the current form: the PR #352 review found the liquidation tooltip set on the old form's label after a symbol change. Account summary (`summary_readout`) and the order form (`side_readout.py`) use it; the bot facts, the session probe and Dev Board's session card have fixed rows and use `ReadoutForm` directly. The order form's fee is a quantity, not money: fees are often below a cent. The estimated liquidation price keeps its tooltip on its value. Dev Board's session card lost two styled stat labels and `field_label` (styling ratchet lowered).
- **Sorting moved into the Engine (2026-10-06, Engine PR #230).** `RowTableModel` served a `datetime` as POSIX seconds (`_sortable`) and the models a `Decimal` as a float (`display_number`) because the Engine's `SpecProxyModel` kept Qt's default `lessThan`, which cannot order a Python object (the PR #351 review). The Engine's `lessThan` now orders `Decimal`s, numbers, `datetime`s (a naive one as UTC) and `None`; both workarounds are deleted and every model serves the value its row holds. `test_spec_table.py` proves a timestamp column and a `Decimal` column sort by value with the raw value in the cell.
- **Changes a user sees.** Unknown values are empty cells, not "—"; positive figures carry no "+" (the minus marks a loss); the trade history's fee asset is its own column; the K-line inspector writes full volumes, not `1.23M`, and no longer sets a monospace font family (`ui-presentation-rule.md` §1); an unknown value sorts last ascending (Qt's order), where `-inf` sorted it first.


**Text cut off in the booted workbench's pictures (2026-10-06).** Three faults the screenshot suite (`test_workbench_screenshots.py`) showed and no check measured; each now has a conformance check that fails on it.
- **The Market Watchlist dropped its columns at every size.** Root cause: the Engine's `_configure_header` (`configure_item_view.py`) gives a spec's `stretch` column Qt's `QHeaderView.Stretch` mode, which sizes it to what the viewport leaves after the other columns. The Watchlist's dock is a little narrower than its four columns, so Symbol got a sliver ("Sym", "BN…"), or kept a stale width with the numbers past the dock's edge; and the dock was that narrow because a `QTableView`'s size hint ignores its columns (`AdjustIgnored`, a fixed 256 px). Fix, in the Engine (PR anhembedded/Sagittarius_Engine#230, which the user approved): a spec's stretch column is an ordinary content-sized `Interactive` column, and `StretchColumnFiller` widens it to fill the viewport but never below its content, measured only when the columns are fitted; every configured view asks for its columns' width (`AdjustToContentsOnFirstShow`). The fix was first written as an app-side `configure_spec_view` wrapper, which said itself the policy belonged in the Engine; it moved there and the wrapper is deleted. Accepted trade-off (Engine review): content that grows after the first fit is not re-measured until a reset. Proof: the Engine's `test_stretch_column.py` (a view leaving the first column a sliver keeps it whole; red under Qt's `Stretch`) and the suite's `columns_shown_whole` (`workbench_text_checks.py`: no visible column narrower than its title and cells, none past the view's edge; red on `tblWatchlist` at all three sizes without the fix).
- **The Backtest chart toolbar was in title case** ("Equity Curve", "Side by Side", "Strategy Indicators", "Buy/Sell Flags", "Wins Only", "Long Only"…) beside View → Chart's sentence case (§4). `chart_controls.py` now reads as the menu; the menu's "Buy/Sell flags" became "Buy/sell flags", and the mode's title "Backtest Engine" (Window menu, mode bar) "Backtest engine". The scan of every menu and toolbar label in the booted app found no other title case but proper names (Monte Carlo, About Sagittarius Elite Warrior). Proof: `toolbar_text_matches_menu` (`workbench_widget_checks.py`): a toolbar action reads exactly as its command's menu item; red on "Equity Curve".
- **The Run setup's Time zone cut off its choice** ("UTC (Coordinated U"). `_choice_field` sizes every list to the form's column (`AdjustToMinimumContentsLengthWithIcon`, so a long strategy name cannot widen the dock past half the window); the time zone's few, long names did not fit it. The time zone list alone now adjusts to its contents: the Run setup dock widens to about 340 px at 1024×700 and every choice shows whole, with no fixed width (§3). Proof: `combo_text_shown_whole` (`workbench_text_checks.py`: a visible list's edit field holds its chosen text); red on `comboBacktestTimezone` (140 px of 233).
- The three checks' probes are `test_workbench_text_check_probes.py`. Not touched: the status bar's always-busy progress bar (`BUG-151`).

**Per-symbol precision (2026-10-06, Engine PR #230).** The Engine's `FormatContext` gained a `precision` and its `KindDelegate` hands a model's `PRECISION_ROLE` answer to the formatter.
- **Port.** `ISymbolPrecisions` (`src/support/ui_kit/i_symbol_precisions.py`) answers a symbol's tick and step as `Precision`s; `support/ui_kit` imports no module, so the filters reach it through this port. `NoSymbolPrecisions` is every model's default.
- **Model.** `RowTableModel` answers `PRECISION_ROLE` for the columns a table lists in `SYMBOL_QUOTED`, from `_symbol(row)`: a `PRICE` column in the tick, a `QUANTITY` column in the step. A quantity of something else is not listed (the positions' leverage, the trade history's fee in its own asset). `use_precisions()` hands a model its filters; `refresh_precisions()` writes every cell again when they become known.
- **Formatter.** A `PRICE` or `QUANTITY` value with a precision is rounded half to even to whole quanta and written with exactly the quantum's decimals (`64,250.1` at a 0.1 tick, `0.015` at a 0.001 step); money keeps two decimals; without one the magnitude rule stands.
- **Desk.** `desk_dependencies_for` builds `OrderMetadataPrecisions` over the venue's own `ISymbolOrderMetadataCache` (never another venue's: `BTCUSDT` has different filters on Spot and Futures); the cache fills when the order panel first reads a symbol's terms, which fetches the venue's whole catalog. `DeskPresenter` hands it to the account tabs.
- **Watchlist.** `MarketMetadataPrecisions` reads the market-data `ISymbolMarketMetadataCache` for the market the mode shows; `WatchlistFilters` fills it on a worker when the person starts the stream (opening the mode opens no connection, `BUG-107`), then the Watchlist writes its cells again. A failed read is a `WARNING` and the magnitude rule.
- **Left, and why.** The backtest trade log formats its own rows in widget code (`trade_log_row`, owned by `EPIC-033L`'s rebuild of the Backtest mode); the order panel's `amount_text` is an editable field's text round trip, already rounded to the step by `order_entry_rules`, not a display cell; the bots' tables have no symbol filters at hand.
