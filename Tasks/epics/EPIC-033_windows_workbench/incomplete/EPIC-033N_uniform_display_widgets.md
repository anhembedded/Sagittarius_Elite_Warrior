# EPIC-033N — Every table, list and read-out is built from one spec per kind

**Status:** 🟡 In progress — tables and the formatter done (P4d); read-outs, grouped trees and per-symbol precision open
**Source:** the user, 2026-10-04 — "ko chỉ cần control thống nhất, mà các widget hiện thị cũng phải thống nhất, ví dụ mấy cái mảng thì phải thông nhất các properti" (not only the controls: the display widgets must be uniform too, e.g. the tables must share the same properties).
**Risk:** 🟡 — every data view changes how it sorts, aligns and formats
**Complexity:** M — 12 item views, every read-out form and every display formatter
**Epic:** [EPIC-033](../README.md)
**Depends on:** Engine W6, EPIC-033C

## 1. Context and problem
The 12 item views in `src` are configured by hand, one file each: selection behaviour is set on 8, edit triggers on 4, header resize modes by 26 separate `setSectionResizeMode` calls, numbers right-aligned in 8 places. The Watchlist gives Symbol ~880 px and squeezes the numbers. Values are formatted by per-screen helpers (`kline_inspector_table_model._format_price`, `trade_log_row._format_datetime`, `trade_log_row._format_compact_usd`, `amount_text.format_amount`, …), so one price prints differently on two screens. Read-outs (Available / Max buy / Total / Est. fee) are label pairs laid out per panel.

## 2. Acceptance criteria
- [ ] Every `QTableView`/`QTreeView`/`QListView` in `src` is built through the Engine's `configure_item_view()` with a `ColumnSpec` per column; no view sets selection, edit triggers, sorting, header resize or alternating rows itself (033B static ban). — Every flat table is (11 views: positions, open orders, holdings, order and trade history, watchlist, database status, K-line inspector, bots, bot orders, bot fills, plus the symbol picker); `item_view_config` in `baseline_stock_controls.json` fell from 69 to 13. **Open:** the four grouped `QTreeWidget`s (metrics detail, out-of-sample comparison, report comparison, timeframe picker) — `configure_item_view` replaces the view's model, which a `QTreeWidget` forbids, and turns on sorting, which would scatter the groups; they need an Engine mechanism for grouped trees, owned by [`BOT-151`](../../../backlog/BOT-151_grouped_trees_from_specs.md).
- [x] A column's kind alone decides its alignment (text left; quantity, price, percent, money right; timestamp and side fixed), width policy (content-sized; one stretch column), sort role (the raw value, never the display string) and display text. — The Engine's proxy and delegate; `test_spec_table.py` (a timestamp column sorts: `RowTableModel` serves a `datetime` as POSIX seconds, since Qt cannot order a Python object — the review of PR #351 found every timestamp column unsorted), `test_positions_panel.py` (`test_pnl_sorts_by_the_number_not_by_its_text`), `test_database_status_table_model.py` (timeframes sort by length). The stretch column is the one whose content varies most (symbol, name, client order id, status), not always the last text column.
- [ ] Every displayed number, price, percent, money amount, duration and timestamp goes through the app's `ValueFormatter` implementation (precision per symbol from exchange filters, one timestamp format, one percent format); the per-screen helpers are deleted. — `AppValueFormatter` (`src/support/ui_kit/value_formatter.py`, `test_value_formatter.py`) writes every table cell, the order book's confirmation questions, the bot facts and the stored-records tile; `_format_price`, `_format_volume`, the row builders' f-strings, `as_number` and the bots' `amount_text`/`signed_text` are deleted. **Open:** precision per symbol — the Engine's `FormatContext` carries only the column key, so the price rule is by magnitude; the backtest trade log (`trade_log_row`, widget rows, 033L) and the order panel's `amount_text` (an editable field's round trip, not a display) still format their own.
- [ ] Every label–value read-out is a `ReadoutForm`; values align to the same column and use the formatter. — Done (P4e) for the account summary, the order form's figures, the bot facts, the trading session probe and Dev Board's Trading Session card: the Engine's `ReadoutForm`, or `ReadoutSlot` (`src/support/ui_kit/readout_slot.py`) where the rows follow the account or the symbol; units in the titles, values by `AppValueFormatter`. **Open:** the backtest report's figures and Monte Carlo summary (owned by `EPIC-033L`, which rebuilds the Backtest mode), Data's stat tiles (`EPIC-033J`), and the grid bot's backtest summary (`grid_backtest_view.py`, a `QFormLayout` of figures with their caveats; owned by `EPIC-033K`, which rebuilds the Bots mode).
- [x] Empty data shows one empty state per view kind (placeholder text in the view, not a separate panel). — `SpecTable` wraps the view in the Engine's `EmptyStateStack`; the history panel keeps its own page because it says three things (reading, an error, no rows).
- [x] 033B's conformance check finds no visible view whose properties differ from its spec. — `item_view_problems` now fails a visible table or tree not configured from its specs (red when `tblWatchlist` loses the mark).

## 3. Design
Declarative column specs as in Qt's own model/view practice and every trading terminal's grids (P5): the model exposes raw values in `Qt.UserRole` and display text through the formatter; the view never decides presentation per screen. Mechanism (spec, kinds, view configuration, read-out form, formatter port) is Engine W6; policy (which kinds a table has, precision per symbol) is the app's (TASK-043's split: the Engine owns mechanism, the app owns policy).

## Implementation notes (written when done)
P4d (the PR with `EPIC-033G`) carries the tables and the formatter; the open criteria above stay with this task.

- **Mechanism.** `RowTableModel` declares `COLUMNS: tuple[ColumnSpec, ...]` and one `_value()` that returns the raw value; `HEADERS`, `RIGHT_ALIGNED`, `_display_text`, `_sort_value`, `SORT_ROLE` and `as_number` are deleted. `RowTableModel.column(key)` replaces the per-model index constants. `SpecTable` (`src/support/ui_kit/spec_table.py`) builds the view through `configure_item_view` with `APP_VALUE_FORMATTER` inside an `EmptyStateStack`, and maps selections through the proxy; `displayed_text()` reads a cell through the view's own delegate, which is what the panel tests assert.
- **Rows hold values.** `PositionRow`, `OpenOrderRow`, `HoldingRow`, the two history rows and `KLineDisplayRow` carry `Decimal`s, floats and `datetime`s instead of pre-formatted text; `display_number()` hands Qt a float to sort on. `DatabaseStatusDTO` carried display strings from the application layer (`"N/A"`, `str(count)`) and the presenter parsed one back (`int(str(...).replace(",", ""))`); it now carries `datetime | None` and `int`.
- **Timeframes.** A timeframe column is `DURATION` with `TIMEFRAME_KEY`: its cell holds seconds, so `1m` sorts before `15m` before `1h`, and the formatter writes the code back.
- **Read-outs (P4e).** `ReadoutSlot` holds the `ReadoutForm` for the rows a `Readout` declares and rebuilds it only when they change (an account learns USDT or USD from its first read; an order form's units follow the symbol), otherwise it only writes values. It takes the old form out of itself at once, not only when the event loop deletes it, and `value_label()` looks only in the current form: the PR #352 review found the liquidation tooltip set on the old form's label after a symbol change. Account summary (`summary_readout`) and the order form (`side_readout.py`) use it; the bot facts, the session probe and Dev Board's session card have fixed rows and use `ReadoutForm` directly. The order form's fee is a quantity, not money: fees are often below a cent. The estimated liquidation price keeps its tooltip on its value. Dev Board's session card lost two styled stat labels and `field_label` (styling ratchet lowered).
- **Sorting could move into the Engine.** `RowTableModel` serves a `datetime` as POSIX seconds because the Engine's `SpecProxyModel` keeps Qt's default `lessThan`, which cannot order a Python object (the PR #351 review). An Engine `lessThan` that orders every `DisplayValue` would make `_sortable` in `table_model.py` unnecessary; it needs an Engine PR and an `engine.ref` bump, so it waits for the user's go-ahead.
- **Changes a user sees.** Unknown values are empty cells, not "—"; positive figures carry no "+" (the minus marks a loss); the trade history's fee asset is its own column; the K-line inspector writes full volumes, not `1.23M`, and no longer sets a monospace font family (`ui-presentation-rule.md` §1); an unknown value sorts last ascending (Qt's order), where `-inf` sorted it first.
