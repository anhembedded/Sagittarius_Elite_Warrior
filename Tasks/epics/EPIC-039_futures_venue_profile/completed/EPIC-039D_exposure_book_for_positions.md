## 1. Context and problem
On Spot, trading keeps an **owner book** per bot (ADR D6): the owner's open orders, an **inventory** (base held net of base-asset fees, with cost) *derived from the venue's history of tagged orders*, never supplied by the owner, and the send times. A Futures bot holds a **signed position** with an average entry, margin and no base asset. It must be derived the same way, and checked against what the exchange says.

### Facts verified on `master-warrior` `076d339`
- `trading/application/owner_book.py` (`OwnerBook`, `nothing_counted`), `owner_books.py` (`OwnerBooks`, `OwnerShare`, `OwnerEventBuffer`: a registration opens a buffer before its reads, replays uncounted fills by trade id under the lock), `owner_inventory_deriver.py` (reads history since `run_started_at`, keeps tagged orders, replays fills joined by exchange order id, minus base-asset fees; checkpoints via `IOwnerInventoryCheckpoints` for runs longer than the venue's 30-day history), `earlier_runs_deriver.py` (what earlier runs left, never traded: `BUG-196`).
- `trading/contracts/owner_budget.py`: `OwnerBudget(max_open_orders, max_exposure_quote, min_order_spacing, max_orders_per_window, window)`; `max_exposure_quote` = "open BUY quote plus the inventory at cost"; `OwnerInventory(quantity, cost)`; caps `OwnerBudgetCaps`.
- `trading/contracts/owner_budget_registration.py` (`OwnerBudgetRegistration`, `OwnerBudgetRefusal`, `…Result`) and the `register_owner_budget` use through the trading session port (read `i_trading_session.py`).
- `trading/application/position_state_reconciler.py` and `position_refresh_service.py` keep `known_open_symbols` and `LivePosition` current from `ACCOUNT_UPDATE`.
- `LivePosition` is **one-way only**: direction from the sign of `position_amt`, `liquidation_price` read from the exchange (`contracts/live_position.py`). `OrderFilledEvent.fee_amount` is `None` for Futures (see 039G; **to verify**).
- A symbol has one lease holder (one owner per symbol), so a position on the symbol belongs to the bot **only if none existed before it started**.
- The bot-side log line to avoid reproducing: `gap reconcile disagrees (inventory_mismatch: saved 0 against 0.00679320 derived from the exchange)` (RESEARCH §7).

## 3. Design
Same shape as the Spot book on purpose (the repo's own pattern, ADR D6: derive from evidence, never supplied), so the executor can ask one question — `IExposureBook.held()` — and a Spot and a Futures answer differ only in type (`INVENTORY` quantity ≥ 0 vs signed position). Cross-checked against `positionRisk` rather than replaced by it, because `positionRisk` is account-level and cannot tell the bot's position from a foreign one (O11). The "earlier runs" idea transfers to "foreign position": what was there before, report it, never trade it.

## Implementation notes (written when done)
**Decisions taken here** (none is an owner-level one; each is reversible and local):
- **Dedup key = the exchange trade id `t`**, as the coordinator specified; `0` or absent is "no trade". A Futures trade id is unique per symbol, the key `ReportedTrades` already uses.
- **What "foreign" means.** The owner's tagged fills leave the position flat (within one step) while `positionRisk` holds more than one step. A bot that had fills and a position that no longer matches them is *not* foreign: it registers, and the difference is a `PositionDivergence` for the guard.
- **Reported, not overwritten.** The task text asks for "the exchange wins" and "never silently overwritten" at once. The book is never changed by a cross-check; the exchange's figure is reported beside the derived one (log WARNING, event, the registration result) and `039F` decides. "Wins" is the decision rule, not a write.
- **Classification.** `POSITION_CHANGED_UNORDERED` = the exchange's amount moved since the last check while no tagged fill was applied; anything else beyond one step is `POSITION_MISMATCH`. A divergence is returned once per pair of figures and again after the two agree. **Assumption not yet verified against a real exchange (recorded in 039F, which confirms before it halts, and in 039L, which settles it on testnet):** `ORDER_TRADE_UPDATE` arrives before the `ACCOUNT_UPDATE` of the same trade (the fake does it so). If Binance reorders them, a bot's own fill would read as unordered for the instant before its fill is applied, and agree at the next check; the guard (`039F`) should confirm before acting. The owner's testnet soak (`039L`) is what settles it.
- **Worst case valuation.** Each case (every open BUY, or every open SELL, filling) is valued as the surviving part of the held position at its entry plus each adding order's own notional (a flip's excess at the average price of the orders that cause it), so the verdict does not depend on the order a ladder is sent in (review of PR #485; `test_the_verdict_does_not_depend_on_the_order_a_ladder_is_sent_in`). An order is refused only when it is the one that raises the worst case past a ceiling, so a reduce-only exit always passes (a position must stay closable).
- **`max_position_notional` is supplied by the caller** (the lower of `capital × leverage` and the bracket cap): this task judges, `039E`/`039H` compute it from the brackets.
- **`OwnerBudgetRefusal.VENUE_NOT_SPOT` became `BUDGET_NOT_FOR_VENUE`.** The old name would lie once Futures registers; a Spot budget with Futures limits is refused too.
- **A Futures registration needs extra reads** (`positionRisk` twice, the symbol's step), none of which Spot makes. `positionRisk` is read **before** the history, so an own order filling between the reads can never make the owner's position look foreign (`test_an_own_order_that_fills_between_the_two_reads_is_not_a_foreign_position`).
- `OwnerBooks.position_of` is the live read for `IExposureBook` that `039H` will use; until then tests call it.
- **`IExposureBook` is a snapshot over the registration's answer**, as Spot's inventory is today (a bot registers again to refresh). A live read would need a new method on `ITradingSession` and its fake; `headroom()` likewise. Both wait for `039H`, the first consumer, which should decide by what the executor reads. `exposure_book_of` has no non-test caller until then.

**Not done, handed on:**
- **No position checkpoint:** a run older than the venue's 30-day history window cannot be re-derived and its registration is refused (`INVENTORY_BEYOND_LOOKBACK`), where Spot's `IOwnerInventoryCheckpoints` bounds the read. `039H` (the first to run a Futures bot for weeks) adds a position checkpoint behind a second port.
- **Fees:** a live Futures fill reports its commission since `039G` (`n`/`N`), so `OwnerPosition.fees` counts it on the live path too, once, by the trade id this task parses; `realized_pnl` is computed from prices, before fees.
- **The fake's `positionRisk` after a restart of the registration** is the oracle here; no testnet run has checked the foreign-position and unordered rules against Binance (`039L`).
- Hedge Mode is out (the connection check already refuses it).
