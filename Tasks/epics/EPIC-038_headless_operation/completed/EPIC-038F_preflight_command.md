## 1. Context and problem
`exchange-status` already checks signature, clock skew, balance and position mode for the Futures Testnet and prints the skew (`exchange_status_formatter.py:38,145`; failure kind `CLOCK_SKEW`). Operators' VPS failures are earlier and plainer: no time sync (`-1021`), a key restricted to an address the VPS does not use (`-2015`, one message for three causes), a key that can withdraw, a full disk that breaks writes while the network works (R5, R6, R9). Nothing checks them together before a bot starts.

## 2. Acceptance criteria
- [x] `preflight [--venue …] [--json] [--skip …]` runs every registered `IPreflightCheck` and prints PASS/WARN/FAIL with a plain-language reason and a remedy each. Exit 0 when none fails; 4 when a check failed for none of the reasons below; 5 when only the operator can fix it (no key, `-2015`, `-1022`, a key that can withdraw); 6 when the exchange is out of reach or a restart can outlast the fault (network, maintenance, `-1021`, an exchange that does not answer). *Evidence:* `test_a_failure_exits_with_the_code_of_its_cause`, `test_missing_credentials_outrank_an_unreachable_exchange_and_a_plain_failure`, `test_a_failure_kind_exits_the_same_through_preflight_as_through_exchange_status`; on the fake exchange `test_a_missing_key_exits_five`, `test_a_maintenance_page_exits_six`, `test_an_exchange_that_cannot_be_reached_exits_six`, `test_error_2015_from_the_exchange_prints_the_checklist_and_exits_five`, `test_a_withdraw_enabled_mainnet_key_fails_once_and_exits_five`; and a real `main.py preflight` run (no keys): exit 5. *Decision:* **D9** (reviewer finding on PR #469): one mapping, `EXIT_CODE_FOR_FAILURE`, shared with `exchange-status`, whose `-2015` and `-1022` moved from 6 to 5; the 038B table and DESIGN §7 were updated with it.
- [x] `ClockSkewCheck`: reads the skew through `IAccountSnapshot`'s connection check (`ExchangeConnectionStatus.server_time_skew_ms`, local minus exchange); WARN above 500 ms, FAIL at or above 1000 ms in either direction; remedy names `timedatectl status`/`chronyc tracking`, `w32tm /query /status`, and says raising `recvWindow` is not a fix. *Evidence:* `test_skew_of_600ms_warns_and_1200ms_fails` (boundaries 0, ±500, 501, 999, ±1000, 1200), `test_a_failing_skew_names_the_tools_and_says_recv_window_is_no_fix`, and the same two figures through the real adapters with the fake exchange's clock skewed (`test_an_exchange_clock_off_by_600_ms_warns_and_by_1200_ms_fails`). Mutation-checked: `>` to `>=`, `>=` to `>`, `abs` dropped each turn tests red.
- [x] `CredentialsPresentCheck`: reports which source the key came from (`env`, `file`, `keyring`) and never the value. *Evidence:* `test_the_credentials_check_names_the_source_and_never_the_value`, `test_no_secret_value_appears_in_the_report` (the fake key and secret are absent from the text and JSON of a report whose checks all ran on them), and the same grep on the fake-exchange run with the mainnet key in the environment. Not exercised: a systemd-credential or file-backend source, which do not exist until 038E (the check prints `CredentialsSource.value`, so a new source needs no change here).
- [x] `KeyPermissionsCheck` and `NoWithdrawPermissionCheck`: a mainnet key's permission list is read back from the exchange (`apiRestrictions`, through the existing `IKeyEnvironmentProbe`); trading for the venue's own market passes, a read-only key fails, **withdrawal enabled fails** with "create a key without withdrawal". *Evidence:* `test_a_withdraw_enabled_key_fails`, `test_a_trading_venue_needs_the_permission_for_its_own_market`, `test_a_read_only_key_fails_on_a_trading_venue`, `test_the_permission_list_is_read_once_for_both_permission_checks`; fake exchange: `test_a_read_only_mainnet_key_fails_the_permission_check_but_not_the_withdraw_check`, `test_a_withdraw_enabled_mainnet_key_fails_once_and_exits_four`. **Limit, stated in the report itself:** a testnet has no permission endpoint, so it is judged by the account's `canTrade` flag and the withdraw check says "a testnet has no withdrawal permission".
- [x] `OutboundAddressCheck` (criterion **amended** from "reports the address the exchange sees": Binance has no request that returns the caller's address): when the exchange answers the `-2015` family it prints the three-cause checklist (key / address / permission), says the restriction is per address and warns about IPv6 on a dual-stack host; the address, with its IP family, is reported only when a `-2015` reply names it (`request ip: …`), which only a mainnet venue's reply gives us, and otherwise the check says "the exchange did not report the address it saw". It passes only when the account was actually read. *Evidence:* `test_error_2015_prints_the_three_cause_checklist`, `test_error_2015_from_the_exchange_prints_the_checklist_and_exits_five`, `test_the_address_the_exchange_named_is_reported_with_its_family`, `test_a_signed_read_that_failed_after_the_time_call_is_never_a_pass`. A third-party echo service was rejected (a new outbound dependency that leaks the host's address). The amendment is recorded in §3 as a departure for the owner to see.
- [x] `DiskSpaceCheck` (data root and `<data root>/logs`; WARN below 1 GiB or 10 %, FAIL below 100 MiB), `DataRootWritableCheck` (writes and removes a probe file), `PythonFloorCheck` (floor 3.12, equal to `requires-python`). *Evidence:* `test_disk_thresholds`, `test_a_small_disk_with_plenty_free_in_bytes_still_warns_below_ten_percent`, `test_a_writable_data_root_passes_and_leaves_nothing_behind`, `test_a_data_root_that_refuses_a_write_fails`, `test_the_python_floor`, `test_the_python_floor_matches_pyproject`.
- [x] Every check is isolated: one that raises becomes a FAIL named for the check and the others still run; a check has a deadline. *Evidence:* `test_a_check_that_raises_is_a_fail_and_the_rest_still_run`, `test_a_slow_check_is_cut_off`, `test_a_factory_that_raises_is_a_fail_for_its_check`. Mutation-checked: removing the join deadline makes the slow-check test hang. **An exchange that does not answer** is exit 6, not 4: an exchange check's deadline (4 × the client's 30 s timeout + 5 s) outlasts the client's own timeout, a timed-out exchange check carries `timeout_cause = EXCHANGE`, and a read still in flight is marked pending in the scope so the later checks fail at once instead of starting it again (`test_a_hanging_exchange_exits_six_not_four_and_is_asked_once`).
- [x] A new check added by a module through `declare_operations` appears in the report with **no** edit to `PreflightRunner`. *Evidence:* `test_a_new_check_appears_without_editing_the_runner`; the composed app's table holds exactly the eight ids (`test_every_declared_check_is_in_the_report_and_nothing_is_placed`); `test_two_modules_claiming_one_check_id_fail_naming_both`.
- [ ] `run` runs preflight by default and refuses on FAIL (exit 4) unless `--skip-preflight` is given. **Handed to 038D:** the `run` command does not exist. The gate it will call is built and tested (`PreflightGate.admit(scope, PreflightPolicy)`; `test_run_refuses_to_start_when_preflight_fails_and_not_when_skipped`), so 038D's remaining work is one call and the flag. A criterion was added to 038D.
- [x] All tests use the fake exchange and fakes; nothing contacts a real exchange. *Evidence:* the unit tests use the module's verified fakes and subclasses of the real ports; the journey tests use the fake Binance server on loopback and assert that no `POST`/`PUT`/`DELETE` reached it. **The clock:** the skew is read from the connection check rather than the machine's clock, so no fake clock was needed there; the deadline test waits on a `threading.Event` for 50 ms of real time (a thread cannot be cut off by a fake clock).

## 3. Design
Chain of independent checks collected through the operations registry (the contribution pattern of `declare_cli`); the module that knows a thing owns its check, so `operations` does not import `trading`. Results are values (`CheckResult` of `CheckFinding`s, one finding per venue or directory), rendered by the `Report` of 038B.

**Deviations from the task text, with reasons.**
- `IPreflightCheck`, `CheckResult`, `PreflightScope` and `IOperationsRegistry` are in `src/core/contracts/`, not `operations/contracts/`: `trading` implements the port and no module may import `operations` (D4, `test_no_module_depends_on_operations`).
- The `operations` handler imports `support/cli_host`, which the boundary policy did not allow a module to do. `rules.py` now lets a module's `cli/` package (only) import that one zone (`_HOST_SUPPORT_ZONES`): the package imports no module code (D7's guard), so no cycle is possible. The policy table's tests pin the new edge and a refused neighbour. 038C's handlers need the same door.
- **Which venues.** `resolve_trading_venues` serves all four venues whatever the configuration says, so "every enabled venue" would fail every operator who has no mainnet key. A venue is in use when it has a key, or when `--venue` names it; if none has a key `credentials-present` fails (exit 5) and the others warn that nothing was checked. A bot's own venue is not visible to `trading`.
- **Departure for the owner: the outbound address.** Reported only when a `-2015` reply names it (mainnet venues only); never from a third-party service.
- A check run that cannot be built or that returns another id is a FAIL, not a crash. A skipped check (`--skip`) is shown as a WARN, so a skip is visible in the report.
- One exchange read per venue per run: `PreflightScope.once` memoises the connection check and the key probe across the five trading checks.

## Implementation notes (written when done)
Written 2026-10-12 on branch `claude/epic-038f-preflight` from `master-warrior` `d1b243f`. Engine at the pinned `f4ef582`, untouched (O7); no dependency, pyproject or settings change.

**What the run found that the task did not say.** (1) `IOperationsRegistry` and `declare_operations` did not exist (038G made the module without hooks); this task created them with `declare_preflight` only and 038C adds `declare_health` after this merges. (2) The venue set is not configurable (above). (3) The key gate's `ConnectFailure` does not carry the permission list and a withdraw-enabled key makes the gated reader answer `WITHDRAWAL_ENABLED`; the checks therefore read the venue's *stored* credentials and ask the probe themselves, and `unreadable_connection` turns the gated answer into a WARN so one fault is one FAIL (`test_a_withdraw_enabled_key_is_one_failure_not_four`). (4) `mypy` rejects an abstract port passed to a generic resolver (`type-abstract`); the two resolves in `declarations.py` carry a commented `type: ignore`, as the Engine's untyped container hides it elsewhere.

**No secret reaches a report or a log.** A finding holds sentences only; a crashed check reports the exception's *type* (its message can hold a signed URL) and logs the traceback under `[preflight]` at WARNING; the key probe's reply text, which is the only free text from the exchange, is the existing `describe_failure` wording.

**Delivery:** branch pushed and a draft PR opened (see the PR); not merged. Epic README, the epics index and the decision record's evidence table are updated; 038D has the gate criterion.
