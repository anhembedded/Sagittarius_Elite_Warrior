## 1. Context and problem
`ICliCommandHandler.handle` returns `None` and "catches the domain's own errors and prints" (`src/core/contracts/i_cli_command_handler.py`); `main()` never called `sys.exit` (`src/main.py`). A failed `exchange-status`, `order-preview`, `order-dry-run` or `trade-once` and a good one both exited 0. (`sync` and `stream` already called `sys.exit(1)` from inside the command on a dispatch failure — control flow by exception, and every other failure exited 0.) `--json` existed once, on `order-preview` (`cli_commands.json:95`), implemented inside that command's formatter, so a second format would have been a second copy of every report. A bare `main.py` opened the interactive prompt, which waits on `input()`.

## 3. Design
Command → `Report` → renderer: the view-model and strategy pattern; a command knows the *what*, a renderer the *how* (single responsibility), and a new format is a new class (open/closed). The exit code is a value the handler returns, not an exception, so a handler stays testable without catching `SystemExit`; the optional return keeps Liskov substitution for every existing handler (they return `None` and mean success). Reuse: `--json` stays the flag (EPIC-021E's precedent); `--format` is its general form; the parser, the table and `declare_cli` keep their shape. Alternatives: `click`/`typer` (a rewrite of the CLI and a new dependency; rejected — the table already exists), raising `CliExit(code)` (control flow by exception, harder to test).

**Where the host lives (D7): `src/support/cli_host/`.** Chosen over a new top-level package or `src/shell/` because the boundary rules already say a support package imports no module — half the isolation is free — while `shell/` is *Main* and may import everything. The guard adds the other half as an allowlist rather than a list of bans: the package may import the standard library, itself, and four kernel contract files (`cli_outcome`, `report`, `i_report_renderer`, `i_report_formats`). Those four stay in `core/contracts/` because `ICliCommandHandler` lives there and `core` may import only `core`, and because modules (`market_data`, `strategy`) return `CliOutcome`; the move to the Engine is therefore this directory plus those four files. The package imports **no Engine symbol either**, so moving it cannot create a cycle. Two consequences recorded: (1) `core/contracts/__init__.py` runs on import and re-exports unrelated contracts — the move trims it; (2) the sub-package of renderers is named `adapters/` (they adapt `IReportRenderer`), because the catalog guard treats any other depth-2 folder under `support/` as a unit needing its own `Capability:` block.

**Exit codes in the mapping.** `5` means "the operator must change something" and `6` "the exchange refused or could not be reached"; `-2015` (key rejected) and `-1021` (clock skew) are `6` as DESIGN §7 states. Not obvious: a `REJECTED` preview and an unusable order exit `2` (not `1`), because `1` is "unexpected" and a restart on it would loop; this is the call a reviewer may overrule.

**The headless dispatch.** The `elif` chain of `_run_headless_mode` became a table of `(app, args) -> CliOutcome | None`; a word absent from it is looked up in `ICliCommandTable` (what `declare_cli` fills), so a command a module declares runs without an edit to `main.py` (D3). `stop()` now runs in a `finally`; before, an exception skipped it. `ExchangeStatusCliHandler` (the prompt's copy) now calls `execute_exchange_status`, which removes a sibling path that would otherwise have accepted `--json` and ignored it.

## Implementation notes (written when done)
Written 2026-10-12 on `claude/epic-038b-exit-codes-reports`, from `master-warrior` `d20065c`. No Engine file, dependency, `pyproject` or setting was touched (O7).

**Findings the task text did not have.**
1. *`sync` and `stream` already exited non-zero* on a dispatch failure, by `sys.exit(1)` inside the command; the four commands that exited 0 on a printed failure were `exchange-status`, `order-preview`, `order-dry-run` and `trade-once`. "`sync` with no data" has no counterpart: `SyncMarketDataCommandHandler` returns `None` on success and raises on failure, so nothing distinguishes an empty sync.
2. *The headless path never called the handlers.* `main.py` called six `execute_*` functions; `ICliCommandHandler` is the prompt's. The widened return type is therefore used by `main()` only through the declared-handler fallback (`test_a_command_a_module_declares_runs_without_an_edit_here`); the six commands' outcomes come from the `execute_*` functions. They are two copies of `sync`/`stream` that were already two; this task did not merge them (out of scope) but removed the third divergence for `exchange-status`.
3. **The Engine's console logger writes to stdout**, so `exchange-status --json | jq` read log lines as the start of the document. `--json` and `--format <non-text>` now switch the console log off for that run through the existing `log.console.enabled` key in `main()` (the dev banner too); a configured log file is unaffected and a traceback still reaches stderr. The stderr retarget is an acceptance criterion of `EPIC-038D` since review round 1 (`#467` closes 038G without taking it); the process test `test_exchange_status_json_is_the_only_thing_on_stdout` is the contract either way.
4. A latent argument-order slip in the first version of the declared-handler fallback (`handle(app, args)` against the port's `handle(args, app)`) was caught by that test before it shipped.

**Decisions taken** (all reversible; the owner may veto): exit `2` for a preview below minNotional and for an unusable order (see §3); `5` for `WITHDRAWAL_ENABLED` and `HEDGE_MODE_UNSUPPORTED` (the application refuses the configuration) and `6` for the five failures the exchange itself produced; `USAGE` (2) in `RestartPreventExitStatus`, so the generated list is `2 3 4 5` (DESIGN §7 says 2 is not restarted; DESIGN §12, §14, `EPIC-038H` and the `cli_outcome.py` docstring were corrected to say the list is generated, review round 1); `trade-once` with unknown credentials or balance is `5`; `KEY_REJECTED`/`BAD_SIGNATURE` stay `6` as DESIGN §7 states (the reviewer asked whether `5` was considered: it was, and DESIGN's `-2015` → 6 stands until the owner says otherwise).
