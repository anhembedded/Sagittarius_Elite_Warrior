# BOT-199 — `main.py logs` colours the values a log call substituted, from a plain log, and filters it

**Status:** ✅ Done (2026-10-20)
**Board:** A viewer inside the app (`main.py logs`, from a pipe or `--file`) shows a plain log with each substituted value (bot id, quantity, reason) in its own colour, found exactly from a catalogue of every log call's template that a guard keeps current; `--level`, `--bot`, `--tag`, `--since`, `--follow`, `--no-color`; byte-identical when not on a terminal, stored records unchanged ([PRO-019](proposal/PRO-019.md)).
**Source:** The owner, 2026-10-20, in Vietnamese: *"cac log ma co [Param] thi param phai co mau luon ban, ... vao tat ca cac log, neu can thi build log manager"* ("logs that carry a param must colour the param ... across all the logs, and build a log manager if needed"); then *"parm y toi la khi ban in log. vi du: \"This bot name {$bot.name}\" thi bot.name la parm, tui ki vong cai do phai khac mau"* (a param is the value substituted into the message; it must be a different colour); then *"đồng ý, làm theo đề xuất C"* (agreed, build option C of PRO-019).
**Risk:** 🟢 — a new command that reads text; no trading, order, stop/close or Engine code, no emitted record changes. The one risk is a wrong colour (a guess shown as exact), which the tests and the `GUESS` style address.
**Complexity:** M — one pure package (parser, catalogue extractor, matcher, filter, meaning table, two renderers, follower, command), one generated file with a guard, one launcher-verb option, runbook.
**Depends on:** [PRO-019](../proposal/PRO-019.md) merged.

---

## 1. Context and problem

On the VPS the owner follows `journalctl -u sew-run -o cat -f`; a WARNING, a tag and a `qty=… price=…` look alike. A viewer that sees only the final line cannot know which words the code substituted (Python keeps `msg` and `args` apart only until a handler formats the record, `logging` docs). `PRO-019` compares four ways under the fixed constraints (stored bytes, the CI scan, the journal and the Engine unchanged) and the owner chose C: a catalogue of every log call's template, read from the source by `ast`, matched to a plain line.

Measured at `5477ce6b` (2026-10-20): 811 log calls (the extractor first missed 9 calls, 3 on receivers such as `_decision_log` and 6 `.log(level, msg)`; both are read now); 618 `%`-style with arguments, 94 f-strings, 66 without params, 33 with a variable message.

## 2. Acceptance criteria
- [x] `main.py logs` reads standard input or `--file` and writes each line; with colour off the output is the input, byte for byte (pipe, `NO_COLOR` non-empty, `TERM=dumb|unknown`, `--no-color`, `--color never`, `rich` missing).
- [x] On a terminal (or `--color always`) the level, timestamp (dim), logger, bracket tag and **params** are styled from one named meaning table (`log_meaning_table.py`); every word is still printed.
- [x] The params of a call whose template is in the catalogue are exact: a `%`-call, an f-string, a call with no params; a line no template fits, or fits ambiguously, is guessed and drawn in a distinct (`GUESS`) style.
- [x] The catalogue is generated by `scripts/render_log_templates.py` and a unit test fails when it is stale; the count of variable-message calls only falls.
- [x] A line that is not a record is written unchanged and never raises; a traceback or other continuation line stays with its record, shown or hidden together.
- [x] `--level` (and above), `--bot` (whole word), `--tag`, `--since` (`2h`, `30m`, `1d`, `today`, `yesterday`, ISO) filter whole records; a bad value is a usage error (exit 2), not a traceback.
- [x] `--follow` on a growing, truncated or rotated file works with no real wait in tests (injected sleep and stop).
- [x] A test formats a record with the application's real format string and parses it back.
- [x] `LOGGING.md` and the headless runbook say how to use it on the VPS with systemd.
- [ ] `ci-local.ps1 -Full` is green on the pull request's head.

## 3. Design
Option C of `PRO-019`, built as in its section 5.

- **Package `src/support/log_view/`** (no Qt, no Engine, no module code): `log_line` (head pattern), `template_model` and `template_extractor` (AST → templates), `template_catalogue_file` (the committed `template_catalogue.json`), `template_matcher` (regex per template, anchor pre-filter, best match by fixed text, ties that disagree return nothing), `message_spans` (exact spans, else guesses, tags), `log_filter`, `log_meaning_table`, `log_renderers_plain` / `log_renderers_rich`, `log_viewer` (a line-by-line state machine, so `journalctl -f` is live), `file_follow`, `log_viewer_cli`.
- **`logs` is a launcher verb** (`LauncherVerb` gained an optional `configure` for options of its own). It builds no application and takes no lock, so it works when the app cannot boot.
- **One colour decision**, in `log_viewer_cli.wants_colour`: `auto` needs a terminal, `TERM` not `dumb`/`unknown`, and an empty or absent `NO_COLOR` (no-color.org: a non-empty value counts); `always` and `never` are the operator's word. `rich` is named by path through `Deferred` and a missing `rich` falls back to plain.
- **Deviations from `PRO-019`:** (1) the proposal said the catalogue records the commit it was built at; a commit sha inside a committed file changes on every commit, so freshness is the guard's job instead. (2) `--color auto|always|never` is added beside `--no-color` (always is needed for `| less -R`). (3) A record is matched on its first line only, so a template whose fixed text holds a newline is cut there; a param that itself holds a newline falls back to the guess.
- **A known cost of a committed catalogue.** The guard runs on the pull request's merge with the base. When another pull request that adds a log call merges first, this one's guard goes red until it regenerates the file (it happened here once: BOT-183 added calls while this was in review). The fix is one command, `python3 scripts/render_log_templates.py --write`, and the failure message says it. A runtime build at each start was measured (1.1 s for 1 973 files) and rejected: a committed file loads in milliseconds and is reviewable in a diff.
- **Not built (Agent decision of `PRO-019`):** emit-time colour (option B), `--journal`, storage or index, a theme file.
