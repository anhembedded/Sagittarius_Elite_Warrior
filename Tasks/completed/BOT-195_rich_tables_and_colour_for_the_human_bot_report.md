# BOT-195 — The human text report prints as a `rich` table on a terminal and stays byte-identical everywhere else

**Status:** ✅ Done (2026-10-19)
**Board:** `bot list`, `bot show` and every text report print as a `rich` table with meaning colour on an interactive terminal; JSON, pipes, the journal, `NO_COLOR`, `TERM=dumb`, a narrow terminal and a missing `rich` keep today's exact bytes, the renderer living in `src/shell` because the CLI host is stdlib-only ([PRO-017](proposal/PRO-017.md)).

## 1. Context and problem
`TextReportRenderer` prints a `Report`'s layout as padded plain text; the owner reads it in an SSH terminal and wants tables and colour there. PRO-017 evaluated `rich` (licence MIT, pure Python, 3.12 floor met, no effect on JSON or Discord) and recommends a terminal-only renderer behind the existing `IReportRenderer` seam.

## 2. Acceptance criteria
- [x] With the text format and stdout an interactive terminal, `TERM` not `dumb`, `NO_COLOR` unset and the terminal at least as wide as the table, a report prints through `rich`; a state word and a profit or loss sign are coloured and still printed as words and signs.
- [x] In every other case (stdout not a terminal, `NO_COLOR` set, `TERM=dumb`, terminal too narrow, `rich` not importable) the output is the `TextReportRenderer` bytes, equal to the existing golden strings.
- [x] `--json` output is byte-identical with a terminal and without one, and `rich` is never imported on that path.
- [x] Output that is not a terminal holds no ANSI escape sequence and no box-drawing character.
- [x] `rich` is named in `requirements.txt` and `requirements-headless.txt` and pinned, with its dependencies, in `requirements.lock` regenerated by `uv pip compile`.
- [x] `Docs/OPERATIONS/headless_runbook.md` says what changes on a terminal, that piped and `--json` output do not, and how to switch it off (`NO_COLOR=1`).

## 3. Design
Two small classes in `src/shell/`, wired by the composition root: `TerminalAwareTextRenderer` wraps the plain `TextReportRenderer` and asks `TerminalState` (stdout is a terminal, `TERM`, `NO_COLOR`, columns) whether a person is reading; only then does it call `RichTextReportRenderer`, loaded through `Deferred` so a piped run, `--json` and a venv without `rich` never import it. The rich renderer turns a section of uniform rows into a `Table`, label and value rows into an aligned block and anything else into lines; one meaning table gives a state word and the sign of a profit figure their style; it raises when the table is wider than the terminal, and the wrapper then prints the plain text (never a shortened cell). Only that refusal and a missing `rich` fall back; a defect or a broken install propagates, and each choice is logged under `App.CliReport` (`[cli-report]`). The renderers sit in `shell` and not in `support/cli_host` because `test_cli_host_imports_no_domain_or_module_code.py` keeps the host stdlib-only, ready to move to the Engine. `ReportFormats.default(text=...)` takes the wrapped renderer, so every report command (`bot`, `status`, `exchange-status`, `alert test`) gets it with no edit. JSON is another renderer and is not touched. Source: PRO-017 §4; `CONSTITUTION.md` P5 (a vetted library) and P7 (the renderer seam).

## 3a. Reuse
`IReportRenderer`, `ReportFormats.register`, `emit_report` and `TextReportRenderer` (the fallback and the byte reference) are used as they are. No UI catalogue row applies (`None: no Qt UI need`).

## 5. Testing
Unit tier (`tests/unit/shell/test_terminal_report_text.py`, 14 tests, and `test_report_formats_wiring.py`, which asks the booted `create_app()` graph for the registered text renderer): (a) not a terminal, `NO_COLOR` set (also empty), `TERM=dumb`: the output equals `TextReportRenderer`'s for the list and show layouts and every `EXCHANGE_STATUS_CASES` report; (b) a terminal too narrow, and `rich` not importable: the same plain bytes; (c) not-a-terminal output holds no `ESC` and no box-drawing character; (d) at a terminal: ANSI present, the words and signs still printed, `RUNNING` green, `HALTED` and a loss red, `STOPPED` uncoloured; (e) the JSON renderer is the same bytes with the terminal on or off and the rich factory is never called on that path; (f) the default registry still holds the plain renderer. The existing 440 `cli_host`, `bots/cli` and `presentation/cli` tests pass unchanged. By hand, under a pseudo-terminal (`script`): a table with colour; piped and `NO_COLOR=1`: the plain text. Not run: a real Windows console (PRO-017 unknowns).

## Implementation notes (written when done)
The dependency pins: only `rich` and its two small dependencies were added to the lock. The wrapper catches the width refusal and `ModuleNotFoundError` for `rich` itself and prints plain text, so a VPS that pulled the code but did not reinstall keeps working. Findings on the way: PySide-free; the report layout has rows of different shapes inside one section (`bot show` mixes label rows and notes), so the renderer groups consecutive rows by shape; the review (round 1) also moved the header from a guess to `has_header`. Not done, by design: `rich` in logging (PRO-017 §1), a `key=value` format, colour on Windows (unrun). The full gate is the PR's `ci-local.ps1 -Full` run.
