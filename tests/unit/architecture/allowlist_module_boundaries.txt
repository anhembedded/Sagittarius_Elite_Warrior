# ---------------------------------------------------------------------------
# presentation -> modules.market_data.application: the transitional dispatch
# surface (27 entries).
#
# What these are: a legacy screen or CLI command builds a market_data Command or
# Query object and hands it to the Engine's ICommandDispatcher. The import is
# only for the *type*, never for a handler - so the coupling is a data shape,
# which is why it was tolerable to leave standing for one phase rather than
# rewrite 20 screens in the same pull request that moved 60 files.
#
# Why they are not simply published in contracts/: publishing them would make
# this coupling permanent and correct-looking. It is neither. Phase 1 replaces
# each dispatch with a call on a narrow port (IHistoricalKlines, IMarketDataSync,
# IMarketStream, ISymbolCatalog, IRangeCoverage), and each replacement deletes
# its line here. Nothing new may be added to this block: a new caller uses a
# port, or there is a new port.
#
# Where they go, by phase:
#   Phase 4  - NINE of the eleven data_management.* lines: the two
#              `database.*` ones, `queries.get_database_gaps`,
#              `queries.get_database_status`, `queries.scan_all_databases`,
#              `queries.audit_database_integrity`, `database.clear_market_data`,
#              `database.prune_empty_shards` and the two bulk-sync ones.
#              NOT the other two: `kline_inspector -> get_historical_klines`
#              retires in PR 1.1 and `scan_coordinator -> list_available_symbols`
#              in PR 1.2, because HLD §3.4 lists `IHistoricalKlines` and
#              `ISymbolCatalog` as **published** ports — a screen using a
#              published port is not a violation, wherever the screen lives.
#              RE-KEYED from Phase 1 on 2026-09-14, when Phase 1
#              was cut into pull requests (epic README §3.3): "a port call
#              retires the entry wherever the file lives" is true mechanically,
#              and wrong here. HLD §3.4 marks database maintenance, gaps, scan,
#              audit and bulk sync **Internal**, and its selection rule is that
#              a port is public when it has a consumer in ANOTHER module. Theirs
#              is the Data Management screen, which the note below sends into
#              `modules/market_data/ui/` in Phase 4 — so publishing seven ports
#              to serve a consumer that is about to move inside the module would
#              publish internals to satisfy a counter. The screen move retires
#              them instead, which is the same phase either way.
#              The original reasoning for deferring that move, unchanged:
#              they were written down as "PR 0.4b, when
#              that screen is rebuilt", on the assumption that 0.4b moves the
#              screen into `modules/market_data/ui/` and turns these into
#              intra-module imports. It cannot: measured, the move needs 35 NEW
#              entries pointing the wrong way — `modules/market_data/ui/` ->
#              `presentation.ui.{kit,assets,common,components,state,qml}` —
#              because a module's `ui/` may import `support/ui_kit` and
#              `support/charting`, and neither exists before Phase 4. Trading 8
#              forward entries for 35 backward ones inverts the number this
#              epic actually watches. EPIC-025A §1.8 records the measurement.
#   PR 0.5   - DONE: the four `sync_market_data.command` lines, via
#              `IMarketDataSync` — the module publishes the capability, the
#              screens depend on the contract
#   PR 1.1a  - DONE: the six `get_historical_klines` lines, via
#              `IHistoricalKlines`
#   PR 1.2   - DONE: the two `list_available_symbols` lines via
#              `ISymbolCatalog`, and the two `get_backtest_range_coverage`
#              lines via `IRangeCoverage`. Both queries were then deleted:
#              once their consumers had moved, nothing in `src/` dispatched
#              either one, and a registration kept for a hypothetical
#              consumer is what PR 1.1a's cleanup established as dead weight
#   PR 1.1b  - DONE: the four `start/stop_live_stream` lines, via
#              `IMarketStream`. These two ports are what `EPIC-025A` §1 assigns
#              to Phase 1; 0.5 deliberately published one port rather than
#              three, so the mechanism is proved by a consumer that runs
#              rather than by three contracts written at once
#   PR 0.4a-2 - DONE: the sync/stream CLI lines left when those commands moved
#              into `modules/market_data/cli/`
