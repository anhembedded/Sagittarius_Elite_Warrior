#
# History of the count: 10 as found (2026-09-13) -> 8 after PR 0.3 -> 41 after
# PR 0.4a -> 38 after PR 0.4a-2 -> 34 after PR 0.5 -> 28 after PR 1.1a -> 24

# The jump at 1.3a is 0.4a's again, and for the same reason: it moved the

# WHY `Order` AND `LivePosition` KEEP THEIR NAMES (PR 1.3b)
#
# HLD 3.4 said "LivePosition NEVER leaves the module; PositionSnapshot is its
# flat DTO", and PR 1.3b does not do that. Measured before deciding: `Order`
# is a frozen dataclass with eleven fields and ZERO methods; `LivePosition` is
# frozen with eight scalar fields, a `LiquidationPrice` (a NewType over
# Decimal) and one pure derivation (`side`, the sign of `position_amt`).
# A `PositionSnapshot` would therefore be field-for-field identical, which is
# behaviour-free churn -- and that is the exact argument PR 1.2 used to KEEP
# the name `BacktestRangeCoverage` rather than rename a DTO that crosses the
# edge. Doing the opposite here would make the epic inconsistent with itself.
#
# So both moved into `contracts/` under their own names, HLD 3.4 is corrected
# to say so, and the 20 entries that named them are gone -- the legacy tree
# may import `modules.*.contracts` freely. What did NOT move is anything with
# behaviour: the policies, the handlers, the mutable session state.

# ---------------------------------------------------------------------------
# legacy -> modules.trading: SIXTY-ONE entries, every one a consumer waiting
# for a port, and every one retired by PR 1.3b.
#
# What these are: a legacy screen, CLI command or service names one of
# trading's types -- an ExecuteOrderCommand it dispatches, a `LivePosition` it
# renders, a TradingSessionState it reads three fields off. Same shape as the
# 27-entry market_data dispatch block above, and retired the same way: PR 1.3b
# publishes IOrderSubmission, ITradingSession and IAccountSnapshot, each
# consumer calls the port instead, and its line goes.
#
# Three of them are worth naming, because they are not dispatches and their
# fix is not just "call a port":
#
# * `-> modules.trading.application.trading_session_state`: RETIRED by PR
#   1.3c-1. It was 5 entries, three of them Presenters reading a MUTABLE,
#   lock-guarded application service directly. Measured, those Presenters read
#   exactly three fields -- `enabled`, `orders_sent_this_session`,
#   `known_open_symbols` -- so `ITradingSession.snapshot()` answers with a
#   frozen TradingSessionSnapshot of exactly those three (HLD 2.4), and the
#   shared mutable object no longer crosses the boundary at all. Both
#   Presenters now take one snapshot where they used to take two or three
#   separate reads, so a screen can no longer observe half of a change the
#   websocket thread is making.
# * `-> modules.trading.domain.live_position` (6) and `.domain.order` (7):
#   HLD 3.4 says LivePosition NEVER leaves the module and PositionSnapshot is
#   its flat DTO. These entries are the measurement of how far that is from
#   true today, and 1.3b's flattening is what closes them. They are the reason
#   `live_position.py` and `order.py` stayed in `domain/` while the order enums
#   moved to `contracts/`: publishing them as they are would have made the
#   wrong shape permanent and correct-looking.
# * `application.use_cases.trading.{arm,disarm}_strategy.handler -> ...
#   trading_session_state` (2): RETIRED by PR 1.3c-1, earlier than planned and
#   by a different route. This was `strategy` reading trading's session state --
#   legal by design once both are modules (HLD 3.4's worked example: arm reads
#   the enabled flag, a `strategy -> trading` call that resolves the cycle), a
#   violation only because `strategy` is not a module yet. The note here said
#   Phase 2 would retire it by moving the caller. In fact both handlers read
#   the same single field the Presenters did, so they took the port in the same
#   change: a legacy file may import `modules.*.contracts` freely, so calling
#   `ITradingSession.snapshot().enabled` needs no entry at all. Phase 2 still
#   moves the caller into `modules/strategy`; what it no longer has to do is
#   change the call.
